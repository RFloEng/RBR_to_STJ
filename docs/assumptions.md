# Assumptions rbr2stj writes

STJ data that is not read from the game files (`assumed` in the sense of the rigorous-conversion rules). The criterion, decided 2026-11-25: each kind is approved **once for the converter** (all RBR stages), not per stage. Corrections are made per source simulator, never per stage: a correction (a value, a table, an omission) applies to every stage of that game. A kind marked `pending` has not been approved; a new kind needs a new approval. All twelve entries were reviewed one by one on 2026-11-25; each row's status is its decision.

| # | Field | Current behaviour | Why it is not from the files | If wrong | Alternative | Status |
|---|---|---|---|---|---|---|
| 1 | `reference.centerline.width` | none (was 3.5 m per side, `_est`) | RBR stores no road width. The schema does not require it (`centerline` requires only `points`; `stj_core.half_widths` returns None without it) | track limits, timing gates and AI corridors that use the width | omit `width` (valid); whether other tools cope without it is untested | **omitted** (decided 2026-11-25): no `width` is written |

| 3 | `surfaces.library[].roughness.sinusoid` | none (was amplitude and `1/BumpFrequency`, `_est`); the raw row stays in `x_rbr.physics` | the unit of the stored frequency is not in the files | wrong roughness | omit | **omitted** (decided 2026-11-25) |

| 13 | BTB: the two directions of a road in one package (`layouts[]`, `layout_only`) | a sibling folder named with `II`, `R`, `Reverse`, `Rever` or `Rev` (or given with `--reverse`) is merged when each line starts and ends within 150 m of the other's end and start, 99 % of the forward line lies within 5 m of the other, and at least half of the forward ground triangles are identical | BTB has no field that links the two folders; the name proposes and the geometry decides, with thresholds of ours | two folders share a package, or stay apart, wrongly; the data of each selection is unchanged either way | `--no-layouts`, or one package per folder | **approved** 2026-11-26 |
